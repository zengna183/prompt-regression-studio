# 系统验收测试

`pnpm test:system` 启动实际 API、Worker 和 Python Core，并连接独立 PostgreSQL / Redis。模型部分使用仅监听本机的确定性 HTTP 服务，所有模型请求都经过正式适配器、项目密钥解密和评测执行代码。它验证系统行为，不评价真实模型的回答质量。

GitHub CI 的 **Real services workflow and fault acceptance** 会为每次运行创建 PostgreSQL 17 和 Redis 7 服务，执行迁移、全部测试并打印 JSON 报告。任一断言失败会使该检查失败。

## 已覆盖的范围

| 场景           | 检查结果                                                                                                          |
| -------------- | ----------------------------------------------------------------------------------------------------------------- |
| 首次开通及登录 | 新数据库迁移、管理员开通、未登录拒绝、会话登录                                                                    |
| 准备评测       | 发布两个 Prompt 版本及评判标准；未审核数据不得发布；审核后发布；模型密钥密文保存                                  |
| 评测与归因     | 真实任务执行及评分；准确定位 3 条退化用例；真实 Python 诊断；段落回退、重跑、证据支持与历史报告读取               |
| 重复提交与重启 | 同时提交两次只创建一组任务；API / Worker 重启后继续完成；Linux 下正常退出，无需强制终止                           |
| 模型限流       | HTTP 429 后有限重试，最终结果不重复入库                                                                           |
| 超时及坏评分   | 记录对应错误，失败结果不能冒充完整评分                                                                            |
| 运行中取消     | 请求尚未返回时取消，晚到的结果不能覆盖取消状态                                                                    |
| Worker 崩溃    | 强制杀死实际进程，等待 BullMQ 重投；有效数据库租约期间延迟执行，不能确认完成或消耗错误重试次数                    |
| 租约到期恢复   | 在隔离数据库中加速租约过期，验证重新接管后完成评测                                                                |
| Redis 网络断开 | 切断 API 到 Redis 的连接；数据库保留待派发记录及失败原因，恢复网络后执行完成                                      |
| 有界并发       | 10 个并发请求读取 200 次比较报告，同时执行 2 版本 × 8 用例 × 3 次重复评测；检查请求错误数、延迟和 48 条结果一致性 |

## 本地执行

先提供**全新的专用** PostgreSQL 数据库和空的 Redis 数据库 15。数据库名必须为 `prs_system_test` 或 `prs_system_test_` 加小写字母/数字后缀，地址仅允许 loopback（本机）。脚本会拒绝已有业务表或已有 Redis 数据的环境。

PowerShell 示例（端口和凭证对应你创建的专用测试服务）：

```powershell
$env:TEST_SYSTEM_DATABASE_URL = 'postgres://eval:eval@127.0.0.1:15432/prs_system_test'
$env:TEST_SYSTEM_REDIS_URL = 'redis://127.0.0.1:16379/15'
pnpm packages:build
pnpm --filter @ai-chat-eval/api --filter @ai-chat-eval/worker build
pnpm test:system:guards
pnpm test:system
```

需要 Node.js 22+、Python 3.12+ 及已安装的项目依赖。Python 默认使用项目虚拟环境或系统 Python，也可设置 `PROMPT_REGRESSION_TEST_PYTHON` 为解释器路径。Linux / macOS 将 `$env:NAME = 'value'` 改为 `export NAME='value'`。

脚本不会读取 `.env`，不会退回到开发环境的 `DATABASE_URL` / `REDIS_URL`，不会删除测试库、清空 Redis 或调用收费模型。运行后关闭测试子进程及连接，数据留在专用测试服务中；再次运行前请重新提供空的测试环境。报告保存至被 Git 忽略的 `artifacts/system-test-report.json`，包括场景结果、延迟和模型请求计数。

## 结果边界与后续验收

- 这是 HTTP、后台执行及数据层的完整链路测试；浏览器界面目前另有组件测试，尚未覆盖真实浏览器点击全流程。
- 并发样本只用于阻止明显功能退化，不能推导公网用户容量、长期吞吐或服务承诺。报告中的 p95 表示 95% 请求不超过的耗时。
- 当前数据库执行租约默认约 30 分钟。测试先证明有效租约被尊重，再仅修改隔离测试记录的时间以加速过期；没有证明生产环境能够秒级恢复。
- 队列是 at-least-once（任务可能重投）执行。数据库结果按任务和用例去重，但进程崩溃后的重复模型调用及其费用仍可能发生；这不是 exactly-once（外部调用恰好一次）保证。
- Redis 测试覆盖连接中断及恢复，不覆盖 Redis 数据丢失、主从切换、磁盘损坏。数据库备份恢复、持续监控及目标部署环境验收属于任务 15。
- 真实付费模型、长时间运行、多实例大规模负载及完整浏览器验收仍需单独执行。完成本项不改变项目的 pre-alpha 状态。
